# Validation corpus

Two complementary layers of validation:

| Layer | Files | Network | Role |
|---|---|---|---|
| **Offline** | `fixtures.ts` | none | pins pipeline behaviour: parsing, 0.6 threshold, `E99` excluded, `E11` at zero weight, zero mistakes on a clean paper. Runs in CI on every PR |
| **Live** | `images/` + `manifeste.json` | InferHub | measures real model quality (RNF-03, RNF-04, robustness). Skipped without a key |

## Offline layer — `fixtures.ts`

7 papers described as data: 5 corrected (with mistakes) and 2 clean. Each fixture contains the
expected annotations, the simulated model JSON answer (with deliberately varied confidences,
including one at 0.31 that must end as `E99`) and the ground truth. Measured by
`tests/corpus.test.ts`:

| Ref | Requirement | Measurement |
|---|---|---|
| RNF-03 | ≥ 80% correct classification | dominant type recovered on the 5 papers |
| RNF-04 | 0 false positives on a paper without errors | 0 mistakes **and 0 classification calls** |

## Live layer — `images/` and `manifeste.json`

11 PNGs generated by `scripts/generer-copies.py` (student writing in the Caveat handwriting font,
teacher annotations in red):

- **8 clean papers**, one per target type: E01 signs, E02 incomplete expansion, E03 special
  products + E04 fractions, E05 domain, E06 powers + E07 roots, E08 transposition + E12
  justification, E09 rounding + E10 units, and one **clean paper**;
- **3 degraded papers** (rotation 2–3°, uneven light, noise, slight blur, reduced contrast) to
  approximate a phone photo: paper 1, paper 6 and the clean paper.

`corpus/demo/` contains the **photos** used by the offline demonstration: papers from the same
student (`corpus/copies-demo.json`), rendered and then passed through a **camera pipeline**
(perspective, uneven light, vignette, grain, blur, shadow cast on a table) to look like real phone
photos — not screenshots. They are generated by
`python3 scripts/generer-copies.py --demo`, never edited by hand.

The four **`v2-copie-1..4.jpg`** are the v2 papers (15 November 2026): Jordan Lee, Grade 12 — B,
final-year level (antiderivatives, derivatives, definite integrals), four tests from October to
November where the sign mistake keeps returning — then disappears on the clean quiz. Their source
is the `copie-v2.html` mockup in the design folder (rendered 1240 × 1240, small grid, teacher's red
pen); the original PNG remains on the design side. The other two (`copie-demo-5/6`) are photos from
the first version of the corpus, kept for the "live analysis" cards.

`corpus/copies-demo.json` is the source of truth for this story: the v2 papers describe the test,
the level, the targeted mistakes and the handwriting lines. The demo answers
(`corpus/reponses/`) were **re-recorded** on these photos with the real model — so if you touch
`copies-demo.json` or the images, you must recapture
(`tests/live/enregistrer-demo.test.ts`, `RECORD_COPIES=v2-copie-1,…` to record only a subset).

## Where to find real papers (external source)

Search carried out on 12 November 2026 (DuckDuckGo/Google/Bing): **photos of real student papers
corrected and annotated by a teacher are not freely downloadable**. What exists:

- **paid** manual correction services (`copie-corrigee.fr`);
- **teacher blogs** that sometimes show an anonymised student's work as an example
  (`mathix.org`, `professeurtheros.fr`, `maths-et-tiques.fr`);
- academic PDFs of **official corrections** (which do not show student mistakes).

**The validated path therefore remains: photograph 5 real corrected papers + 2 clean papers**
(protocol below). Meanwhile, `corpus/demo/` provides 6 photorealistic "photos" — including four
final-year papers from the same student — and `corpus/images/` the controlled synthetic corpus.

`manifeste.json` carries the ground truth (`fichier`, `dominant`, `degradee`): it is **generated at
the same time as the images**, so the bench's expectation cannot drift away from the corpus.

```bash
python3 scripts/generer-copies.py                 # regenerate images + manifest
INFERHUB_API_KEY=… npx vitest run tests/live/     # measure (≈ 13 min)
```

Results and analysis: [`../docs/VALIDATION-MODELE.md`](../docs/VALIDATION-MODELE.md).

> **What the synthetic corpus does not measure.** A generated paper has no real handwriting, no
> fold, no reflection and no sloppy framing. It validates the prompts, the taxonomy and resilience
> to digital degradation — not the reading of real handwriting.

## Protocol on real papers (day-1 go / no-go)

1. Photograph **5 real corrected papers** at high-school level (maths), including at least one with
   a faulty expansion and one with a sum of fractions.
2. Photograph **2 papers without errors** (the teacher annotated nothing).
3. Put the 7 photos in `corpus/images/reelles/` and add their entries to the manifest
   (`"reelle": true`).
4. Run the bench: `INFERHUB_API_KEY=… npx vitest run tests/live/inferhub.test.ts`.
5. **Go** if: ≥ 4 papers out of 5 have a correct dominant type **and** the 2 clean papers return
   "no mistake detected".
6. **No-go** after 3 prompt rewrites: switch to plan B (no API, limited local diagnosis). Decide
   that same evening, not on the last day.

Demo mode (`src/pipeline/demo.ts`) is recaptured the same way:
`INFERHUB_API_KEY=… npx vitest run tests/live/enregistrer-demo.test.ts` writes the real answers into
`corpus/reponses/`.
